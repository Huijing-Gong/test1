## 已落实的预算

| 项目 | 约束 | 保留的玩法行为 |
|---|---|---|
| 远程能量镖 | 每个世界场景最多 24 个活跃／保留对象，懒创建后复用 | 每帧实际飞行、扫掠碰撞与墙体遮挡不降频 |
| 能量镖撞击 | 最多 8 组短粒子，每组最多 8 粒，无实时灯光 | 满额仅省略次要火花，不改变已发生的伤害 |
| Prism 波纹 | 复用预警／释放时已有的地面采样及固定顶点数组 | 开始准备与真正释放仍重新检查掩体、断层；身体或已采样地面移动后缓存失效 |
| 维修扫描 | 最多 4 个主要甲片覆盖层，共享原网格与扫描材质 | 只在有效维修及短暂成功淡出时开启，受击／死亡优先级不变 |
| 远处细节 | 相机距离超过 24 米关闭小碎屑、子弹尾迹、维修扫描与拳头细线 | 不关闭敌人 AI、拳头判定、波纹、冲撞方向提示和维修主连接线 |
| 次要程序动画 | 远处维修萤待机、冲锋兽装饰性落脚约 8 Hz；悬浮摇摆与细微旋转简化 | 攻击、受击、死亡及实际身体移动／安全地形查询仍运行 |
| 发光 | 继续共享材质／核心 Shader，无逐怪实时灯光 | 状态亮度与死亡熄灭保留 |

石甲怪的 Animator 不停用或降频：真实拳头位置仍参与伤害判定。不能为了省动画开销破坏动作与命中的对应关系。

`EnemyTransientPool` 使用 Unity `ObjectPool<T>`，并额外检查活跃数及不同子弹 Prefab 的总保留数；`maxSize` 本身只限制回收保存的对象，不能当作活跃上限。当前地图只有一套远程子弹。达到 24 发上限时不生成第 25 发，统计 `DroppedDarts`；以后大量复制远程怪时应检查此计数，不盲目扩大池。参见 [Unity ObjectPool 构造参数](https://docs.unity3d.com/6000.0/Documentation/ScriptReference/Pool.ObjectPool_1-ctor.html)。

回收时清空尾迹、旋转、剩余寿命、拥有者及事件订阅。菜单、拥有者死亡、新游戏和场景卸载会清掉活跃对象；新游戏可以保留空闲池，卸载世界则销毁整个场景池。重复回收不会销毁已归还的对象。

## 实测，不把编辑器结果当浏览器结果

本机 Apple M2，Unity `6000.3.21f1`，Metal。以下是一次固定夹具微基准，不是全地图帧率保证；直接创建路径只测创建，而池路径包含生成、初始化与回收，比较偏保守。

| 测试 | 直接创建／原路径 | 复用／缓存路径 |
|---|---|---|
| Editor，96 发 | 7.90 ms | 0.51 ms，预热后新增子弹对象 0 |
| 独立 Mac 程序，96 发 | 3.085 ms | 0.728 ms，预热后新增子弹对象 0 |
| Editor，120 次波纹绘制 | 修改前 26.22 ms（较早独立基准） | 1.86 ms，无额外地面查询 |
| 独立 Mac，120 次缓存波纹 | 未在独立程序保留旧实现 | 2.115 ms，无额外地面查询 |

独立程序的五类模型／反复受击／撞击夹具采样 180 帧：关闭夹具自身 VSync 后主线程中位 1.002 ms、P95 1.199 ms，峰值 182 draw calls。AI 在此微基准中关闭，场景是临时平地，没有整张地图、玩家或 Boss，因此这些数值不能用于宣布正式游戏或 WebGL 达到某个 FPS。

独立程序的 `GC Allocated In Frame` 记录累计 17,568 字节，包含测试驱动等工作，不是每发子弹分配量。Editor 的 `GC.GetAllocatedBytesForCurrentThread()` 在当前运行时不可用，返回 0 **不构成零 GC 证明**。已有证据只证明预热后的子弹 GameObject 不再反复创建；继续用实际 Profiler 核对正式战斗的分配峰值。

完整正常 Unity 窗口的战斗回归通过：实际空挥与命中、拳头轨迹、波前遮挡和真实 Space 起跳／落地、子弹碰撞、维修优先级、有限治疗、死亡／新游戏清理。性能专项还通过对象数量上限、重复回收、移动平台缓存失效、远处细节关闭且攻击预警保留。测试没有保存原地图／Prefab，原存档未变。

## 透明效果检查

使用 URP Rendering Debugger 的 Transparent Overdraw，而不是从 PNG／Shader 文件大小推断 GPU 开销；小怪自定义 Shader 已补充调试变体支持。调试时隔离小怪渲染，避免不支持调试视图的既有地形／树木 Shader 被误判为小怪热点。参见 [Unity Rendering Debugger](https://docs.unity3d.com/6000.0/Documentation/Manual/urp/features/rendering-debugger-reference.html)。

本次在真实地图中检查单只 Prism 同时显示预警波纹和 4 个维修覆盖层：主要区域约 1 层，局部细边约 2 层，未出现 8 层饱和热点。该结果不代表多只 Prism 波纹叠加时一定安全；大量摆放后仍需以实际镜头检查。地面填充保留一层，修复扫描只覆盖主要甲片，小碎屑按距离剔除。

## 在 Unity 里复测

先保存场景并退出 Play，再使用：

- `Tools > Enemies > Check Enemy Performance Budget (Play)`：对象池、真实墙碰撞、死亡／菜单／新游戏清理、波纹查询、移动平台、扫描上限和透明重叠截图。
- `Tools > Enemies > Check Combat Ground And Hit Foundations (Play)`：完整玩法回归；用正常编辑器窗口，batchmode 不能验证鼠标锁定相关的真实挥剑输入。
- `Tools > Enemies > Build Isolated Enemy Performance Probe (Mac)`：构建临时夹具。测试场景构建后自动移除；输出在系统临时目录而非 Assets。单独运行应用会输出 `native-report.txt` 和五类模型截图。

性能专项日志：`/tmp/anca-enemy-performance-final.log`。完整回归日志：`/tmp/anca-enemy-performance-foundation4.log`。独立 Mac 结果：`/tmp/anca-enemy-performance-native-final/native-report.txt`。截图目录为系统临时目录下的 `anca-enemy-performance`；临时文件可能被系统清理，重要结果另行归档。

## WebGL 尚未实测

本机这版 Unity 只有 MacStandaloneSupport，没有 WebGL Build Support，因此不能诚实给出浏览器成绩。没有自动下载安装大型模块，也没有把原生结果换算成 WebGL 帧率。

安装匹配版本的 WebGL Build Support 后，可先运行 `Build Isolated Enemy Performance Probe (WebGL)` 检查小怪模型、Shader、池上限与缓存路径在浏览器端是否可用，再在实际游戏 WebGL 中验证：

1. 浏览器正常开局，记录浏览器／硬件／分辨率；通过 HTTP 服务打开构建，不直接打开本地 HTML。
2. 在隐藏宝箱和塔前，连续进行远程射击、Prism 波纹、维修和受击；分别查看 CPU、GC、draw calls 与 GPU／透明重叠成本，不把首次资源加载混进稳定阶段。
3. 逐步增至实际预计同时出现的怪物数量；检查子弹没有穿墙、波纹跳跃躲避正确、维修可中断、池不增长，以及远处提示仍清楚。
4. 菜单、死亡、新游戏、往返副世界后复查池与残留效果。正式网页测试结束前不能把此项标为通过。

独立浏览器夹具的文件输出属于浏览器虚拟文件系统，不能照搬 Mac 的 `/tmp` 报告路径或依赖 `Application.Quit` 自动关闭页面；应使用浏览器控制台与 Profiler，视觉／人工检查仍不可省略。
